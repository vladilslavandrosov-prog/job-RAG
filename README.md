# job-RAG

Документация и разбор кейсов по корпоративной RAG-системе для брокера/инвестиционного советника.

## Описание системы (итоговый синтез)

[`docs/system-description.md`](docs/system-description.md) — финальная выкладка по всей базе: архитектура (компоненты, полный маршрут данных, ролевая модель, сайзинг), бизнес-портфель (пять практик, пилотная экономика, что реально волнует покупателей), и честный список нерешённого. Собрано тремя ролями (архитектор, аналитик, критик), сверено по иерархии приоритета источников ниже. Начать знакомство с базой лучше всего с этого документа.

## Приоритет источников (при расхождении фактов между материалами)

1. **[`docs/rfi-responses/`](docs/rfi-responses/README.md) — наивысший приоритет.** Документ от разработчика платформы (инженерная/архитектурная команда вендора), а не от продаж или маркетинга. При расхождении с любым другим материалом в этой базе (презентации, лендинг, живые встречи, даже пилотные ТЗ) — **верным считается то, что написано здесь**, пока не появится более новый документ той же категории.
2. `docs/analysis/case-03-pilot-tz-ai-guard.md` — пилотное ТЗ с юридической силой для конкретного пилота (количественные критерии приёмки).
3. `docs/accounts/` — дословная запись живых встреч; достоверна как факт «что сказали», но сказанное сейлзом/инженером на встрече может быть неточным или упрощённым по сравнению с письменным источником уровня 1.
4. `docs/sales-enablement/` — маркетинговый питч; самый низкий приоритет для фактической точности, полезен только для аргументации и позиционирования.

## Структура

- `docs/sources/` — исходные материалы (ТЗ, логи диалогов с системой).
- `docs/analysis/` — разбор кейсов: соответствие ТЗ, найденные дефекты, архитектурные предложения.
- `docs/glossary/` — глоссарий: базовые понятия RAG-систем простыми словами, с привязкой к проекту.
- `docs/platform/` — база знаний по интерфейсу платформы: разбор экранов по скриншотам.
- `docs/demo-retail/` — демо-кейсы для ретейла: сценарии использования платформы и (на втором этапе) пакет документов под них.
- `docs/sales-enablement/` — разбор внутреннего материала по методике продаж платформы (лендинг для сейлз-менеджеров): аргументы питча, кейсы клиентов, инструкции по демо, разбор возражений.
- `docs/accounts/` — живые, реальные аккаунты продаж: разбор встреч с конкретными заказчиками по мере их поступления (не гипотетические кейсы), с фокусом на вопросы и заинтересованность заказчика.
- `docs/rfi-responses/` — формальные письменные ответы вендора на технические запросы (RFI/due diligence): самый строгий и самокритичный источник в этой базе, с явным разделением «реализовано / настраивается / дорожная карта / не поддерживается».

## Кейсы

- [`docs/analysis/case-01-d8-014-brief.md`](docs/analysis/case-01-d8-014-brief.md) — приёмочный разбор диалога подготовки брифа к встрече с клиентом D8-014.
- [`docs/analysis/case-02-tz-deep-analysis-and-proposals.md`](docs/analysis/case-02-tz-deep-analysis-and-proposals.md) — глубокий анализ ТЗ (противоречия, пробелы), предложения по архитектуре и новые кейсы использования агента.
- [`docs/analysis/case-03-pilot-tz-ai-guard.md`](docs/analysis/case-03-pilot-tz-ai-guard.md) — новое ТЗ оплачиваемого пилота с компонентом AI Guard: скоуп работ, тестовые сценарии и критерии приёмки; закрывает давний открытый вопрос про периметр данных и модель `OpenAI/gpt-5.4 · veai`. Плюс [`case-03-pilot-execution-plan.md`](docs/analysis/case-03-pilot-execution-plan.md) — практический план исполнения: чек-лист готовности, календарь по этапам, матрица всех 17 тестовых сценариев.
- [`docs/analysis/case-04-sales-pitch-critique.md`](docs/analysis/case-04-sales-pitch-critique.md) — критический разбор презентации «Единый корпоративный ИИ-слой» для команды продаж: где заявленное не совпадает с реально задокументированным поведением платформы, готовые ответы на возражения покупателя.
- [`docs/analysis/case-05-itq-group-full-deck-diff.md`](docs/analysis/case-05-itq-group-full-deck-diff.md) — разбор изменений в новой 39-слайдовой презентации «ITQ Group» (портфель из 5 практик) против старой 12-слайдовой: что из находок кейса 04 исправлено, что нет, новые риски от увеличившегося объёма материала. Плюс ревизия 2 (35 слайдов) — целенаправленные точечные исправления (RBAC, роль Veai/DLP, каталог моделей) и новый технический дефект (нумерация разделов).
- [`docs/analysis/pokrytie-maskirovaniya-perechen-d8.xlsx`](docs/analysis/pokrytie-maskirovaniya-perechen-d8.xlsx) — построчное сопоставление 30 пунктов заказчиковского [«Перечня информации, составляющей коммерческую тайну АО «Инвестиционная компания Д8», версия 3.0»](docs/sources/commercial-secret-perechen-d8-v3.pdf) (Приложение №2, приказ ГД от 18.05.2026 № 26-18/05-1) со встроенными типами PIIType платформы: статусы «Маскируется» (4) / «Частично» (5) / «Не маскируется» (21) по каждому пункту, нумерация — как в оригинале заказчика. Для всех пунктов, требующих уточнения, — вопрос к заказчику (с примером и, где применимо, технической рекомендацией), плюс разбивка «не маскируется» на потенциальный кастомный PIIType (8 пунктов) vs структурно другой слой контроля/DLP (13 пунктов), со ссылкой на встроенный DLP-механизм платформы (RFI §5.3). Прошло независимое ревью тремя ролями (аналитик/архитектор/критик): сверено с оригиналом скана (исправлена одна пропущенная формулировка), исправлена ошибка по IP-адресам (п. 3.3, уже покрыто типом IP), помечен риск для критерия приёмки пилота (номер договора). Плюс [`instrukciya-pokrytie-maskirovaniya-perechen-d8.docx`](docs/analysis/instrukciya-pokrytie-maskirovaniya-perechen-d8.docx) — сводная инструкция в 4 разделах (источник и контекст, методология, результаты покрытия, открытые вопросы к заказчику) в цветах платформы.
