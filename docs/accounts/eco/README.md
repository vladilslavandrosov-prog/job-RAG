# Аккаунт: АО «ЭКО РЕСУРС» (СМК/пищевая безопасность)

> **Название подтверждено документами:** АО «ЭКО РЕСУРС», судя по колонтитулу процедур — «Система менеджмента качества и безопасности». Рабочий домен на платформе называется «Эко», пользователь — `eco_user@itq-group.com`.

> **Не путать с другими аккаунтами.** В базе четыре разных, не связанных между собой заказчика:
> - **АО «Инвестиционная компания Д8»** — брокер, основной оплачиваемый пилот (материалы — в `docs/analysis/case-*`, `docs/platform/`, не в `docs/accounts/`).
> - **[`../mz-arsenal/README.md`](../mz-arsenal/README.md)** — ОАО «Машиностроительный завод «Арсенал», оборонное предприятие, тёплый лид на стадии демо.
> - **[`../dairy-holding/README.md`](../dairy-holding/README.md)** — молочный холдинг, пищевая отрасль, только что прошёл первую discovery-встречу.
> - **Этот аккаунт — АО «ЭКО РЕСУРС»** (пищевая/потребительская продукция, СМК по ISO 22000/ISO 9001, цеховая документация в 1С-8), пилот **уже технически запущен на платформе** — есть живой пользователь, домен и коллекции документов, идёт тестирование ответов ассистента по СМК-регламентам.
>
> Если в переписке встречается просто «Эко» без уточнений — это про этот аккаунт, не про демо-кейс `docs/demo-sinaps/` или что-либо связанное с Д8.

## Что известно на данный момент

- **Платформенная идентичность:** пользователь `eco_user@itq-group.com`, без назначенной Персоны (RLS не настроен), с прямым доступом к домену **«Эко»** через роль `Domain Only Access Role`.
- **Домен «Эко»** содержит 3 коллекции: `eco` (misc), `Fedoseeva` (regulation), `uploads_user_eco_user__misc` (misc, похоже на личную папку загрузок самого `eco_user`) — подробности и открытые вопросы по настройке доступа см. [`access-audit.md`](access-audit.md).
- **Пилотное тестирование ответов** ассистента по регламентам СМК: 18 вопросов в 6 группах, 61% с пробелом (частичный/нет ответа) — из них **7 подтверждены как ошибки поиска** (ответ реально есть в документах, платформа не нашла), **2 подтверждены как корректные ответы** (в корпусе действительно нет нужной детали), **2 требуют недостающих документов**. Найдена вероятная корневая причина большинства ошибок — см. [`pilot-test-01-analysis.md`](pilot-test-01-analysis.md).

## `converted-for-upload/` — что сделано и с какими оговорками

**Как конвертировано:** для каждого `.doc` текст извлечён через `catdoc -s cp1251 -d utf-8` (единственный инструмент из опробованных, который вообще открыл эти файлы — ни LibreOffice, ни pandoc не смогли, см. `pilot-test-01-analysis.md` §3), переразбит на абзацы по пустым строкам (снимает искусственный перенос строк, который catdoc делает для вывода в терминал) и упакован в новый `.docx` через `python-docx`. Оригинальный `.doc` не редактировался и остался в `source/` без изменений. Документ ПР-08-00-14 собран тем же способом (`python-docx`), но из текста, полученного напрямую в чате, а не через `catdoc`.

**Проверено:**
- Все 25 файлов открываются в `python-docx` без ошибок.
- Все 25 — структурно валидный OOXML: ZIP не повреждён, обязательные части (`[Content_Types].xml`, `word/document.xml`, `_rels/.rels`) на месте, весь XML внутри well-formed (независимая проверка `zipfile`+`xml.etree`, не полагается на то же средство, что создавало файлы).
- Выборочно сверено, что ключевые цитаты из анализа теста (например, «0,8» в Методике №38, «руководит производственным процессом» в И-16-01-11) присутствуют в тексте после конвертации.

**Честная оговорка:** LibreOffice в этой среде не смог сконвертировать в PDF даже новые, только что созданные `.docx` (включая пустой тестовый файл из одной строки) — «Error: source file could not be loaded» на всех попытках, при том что `.pptx` в этой же среде эта версия LibreOffice конвертирует нормально (см. презентации выше в этом аккаунте). Это похоже на поломку именно Writer-фильтра в текущей среде, а не признак проблемы в самих сгенерированных файлах — структурная проверка выше независима от LibreOffice и её не использует. Но раз я не смог визуально отрендерить результат, **таблицы и форматирование из оригинала не сохранены** — только текст, разбитый на абзацы (для загрузки в RAG-коллекцию это не критично: важен текст для индексации и цитирования, не вёрстка, но проверьте сами перед массовой загрузкой на 1-2 файлах, особенно там, где в оригинале была таблица — например, Методика №38, где высота сброса представлена как таблица, а тут — плоский текст с теми же числами).
