## Сценарий 3 платформы (доступность данных через API/JOIN Bitrix+DWH)

**Что подтверждено:** запрос «дай информацию по счетам клиента с номером договора BP33431 и реквизиты клиента» отработал корректно через прямой чат-интерфейс — данные из `bitrix.crm.default.items` и `"test DWH".dwh.report.account` соединились правильно, вернулись все договоры клиента (BP33431, BP70746, BP79140), счета по каждому, реквизиты, с явным указанием источника. Прежняя проблема («подхватился отчёт брокера вместо DWH») здесь не воспроизводится.

В 08:49 Андрей Савичев прислал сам SQL-запрос, подтверждающий починку на уровне запроса к данным:

```sql

    a.ACCOUNT_ID,
```

Комментарий разработчика: «как часы».

**Что НЕ подтверждено — важная оговорка:** обе сегодняшние демонстрации — через прямой чат-интерфейс, не через n8n/MCP. Накануне (07.09, вечер) именно путь через n8n (`data__ask` как MCP-вызов) был сломан отдельно от самого запроса к данным: сначала «Fetch failed» в n8n, после донастройки модели ошибка ушла, но ответ через API всё ещё не совпадал с ожидаемым, при том что «через интерфейс ответ корректный» (комментарий разработчика). Починка данных/запроса, подтверждённая сегодня утром, **не равна** подтверждению, что тот же результат придёт через n8n — это отдельный, ещё не перепроверенный путь.

**Статус:** Сценарий 3 — данные и запрос к ним подтверждённо работают через чат; путь через n8n/MCP требует отдельной проверки, прежде чем закрывать сценарий целиком.

## Рабочая гипотеза: что реально проверяет заказчик

Демонстрации «работает через интерфейс чата» не закрывают вопрос сами по себе. Судя по тому, что тестировщик (Юрий) систематически настаивает на проверке именно через n8n, а не только через чат, — реальное требование приёмки, вероятно, **паритет между интерфейсом и программным вызовом (n8n/MCP)**, а не просто корректный ответ в чате. Похоже, пилотный сценарий использования на стороне Д8 предполагает, что платформу как источник данных дёргают их собственные автоматизированные процессы (workflow в n8n), а не только сотрудник вручную через чат. Формулировку «через интерфейс ответ корректный» как аргумент в пользу закрытия кейса стоит трактовать осторожно, пока то же самое не подтверждено через n8n.
