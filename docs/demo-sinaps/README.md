# Демо-стенд платформы «Синапс»

> «Синапс» — прежнее рабочее название платформы (см. [`docs/sources/synaps-insight/`](../sources/synaps-insight/README.md)); текущее официальное название — «Камерата» (ребрендинг 20.08.2026). Материалы этого кейса названы и оформлены под «Синапс» как есть, без переименования — сохраняем исходную поставку.

Готовый комплект для демонстрации платформы: 6 бизнес-сценариев на **двух синтетических компаниях-эталонах**, с полным набором данных, документов и чек-листом технической настройки. Не гипотетический план — уже собранный, загружаемый пакет.

## Компании-эталоны

| Компания | Профиль | Держит сценарии |
|---|---|---|
| **«Меридиан»** | Диверсифицированный пром-торговый холдинг (B2B) | 1 (Досье 360°), 2 (Маржа), 4 (RBAC), 5 (ИБ/DLP), 6 (Юрассистент/RAG) |
| **«Полка»** | Розничная сеть / e-com | 3 (Голос клиента + цены конкурентов, агент в интернет) |

Все данные синтетические, помечены «ДЕМО».

## 6 сценариев — коротко

| № | Название | Компания | Что проверяет |
|---|---|---|---|
| 1 | Досье 360° по клиенту | Меридиан | Сборка ответа из 5 источников (учётка, CRM, договор, протоколы, переписка) |
| 2 | Разложение маржи по факторам | Меридиан | Диалог с данными + честность RAG (версия-ловушка: устаревшая политика скидок рядом с действующей) |
| 3 | Голос клиента + цены конкурентов | Полка | Агент безопасно ходит в интернет через AI Guard по белому списку |
| 4 | RBAC: один вопрос — разные ответы | Меридиан | Права наследуются из систем-источников, не прописываются в промпте |
| 5 | ИБ-правило «наружу не уходит» | Меридиан | Маскирование ПДн + семантическое (не regex) распознавание коммерческой тайны |
| 6 | Юрассистент: претензия со ссылками | Меридиан | RAG-ядро: цитаты на конкретные пункты, честный отказ при отсутствии ответа в корпусе, работа с версиями документов |

Полное описание каждого сценария (вопрос в чат, источники, ожидаемый ответ, что раскрывает) — в [`00_GUIDE_demo_sinaps.md`](00_GUIDE_demo_sinaps.md) и визуально в [`Sinaps_demo_guide.html`](Sinaps_demo_guide.html).

## Порядок настройки

1. Залить SQL (`Meridian_load_postgres.sql`, `Polka_load_postgres.sql`) в отдельные схемы/базы — источники не должны смешиваться.
2. Векторизовать документы из `Meridian/documents/` и `Polka/documents/` — RAG-корпус.
3. Настроить семантический слой по таблице `data_catalog` (в обеих базах) — бизнес-термин → таблица → поле → метка чувствительности.
4. Завести демо-пользователей и роли (`roles_matrix`, `access_class` в `deals`) — см. таблицу демо-пользователей в гайде.
5. Загрузить `secrets_base` в модуль DLP Secret.
6. Для «Полки» — настроить агента и белый список сайтов (`whitelist_sites.md`), либо оставить синтетические слепки (`competitor_prices`, `marketplace_reviews`) для демо без живого интернета.

Детальный пошаговый чек-лист (45 шагов, 12 этапов, со статус-колонкой) — [`Sinaps_setup_checklist.xlsx`](Sinaps_setup_checklist.xlsx).

## Как подбирать сценарии под встречу

- **Бизнес / C-level:** начинать со сценария 2 или 1 (самый доступный «вау»), агент (3) — под конец.
- **Функция** (юристы/финансы/сервис): один профильный (1, 2 или 3) + сценарий 5 как страховка по безопасности.
- **ИТ / ИБ:** сценарии 4 и 5 обязательны — снимают возражения «увидит лишнее» и «утечёт наружу».
- **По отраслям:** финансы → 1, 2, 4, 5; промышленность/энергетика → 1, 2; ритейл/e-com → 3, 2.
