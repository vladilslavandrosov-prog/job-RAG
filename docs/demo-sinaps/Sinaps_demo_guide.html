01 · Принцип демо

Не «спросили — ответило», а «где наивный ИИ ломается»

Голый ChatGPT или простой чат-по-документам отвечают красиво, но на реальных корпоративных задачах спотыкаются: не видят данные компании, не различают права доступа, выпускают наружу лишнее. Каждый сценарий стенда построен так, чтобы этот разрыв был виден.

Что показывает любой сценарий

  • Сборку из нескольких источников — ответ собирается из разных систем и документов, а не из одной таблицы
  • Ссылки на источник — видно, откуда взялась цифра или пункт
  • Встроенную безопасность — права и маскирование работают по ходу, а не отдельным слайдом

Три типа сценариев из платформы

  • Диалог с данными — вопросы к данным на русском через семантический слой
  • Знания / RAG — ответы по документам со ссылками на пункты
  • Агенты процессов — действия, сбор данных, выход во внешние источники
Фон для всех сценариев: единый шлюз AI Gateway маршрутизирует запрос на подходящую модель (облачную или локальную), развёртывание 100% on-premise, каждый запрос — в сквозном аудите.

Сценарий 1 · Компания «Меридиан» Знания + данные

Досье 360° по клиенту

Полная картина по клиенту, собранная из пяти систем в один ответ со ссылками на каждый факт.

Вопрос в чат

«Собери картину по клиенту "Вертикаль": выручка и дебиторка, стадия сделок, что мы обещали, дедлайны и риски срыва».

Источники (это и есть суть)

учётная система (выручка, дебиторка) · CRM (сделки) · договор · протоколы встреч · переписка. Пять разных источников — в одном ответе.

Какие функции проверяет
● Сборка из нескольких источников Знания / RAG Диалог с данными Маскирование ПДн Аудит
Что раскрывает

Ни один отдельный отчёт и ни один чат-по-документам такого ответа не дадут — нужна склейка структуры (БД) и текста (договор, письма, протоколы) в один нарратив. ПДн контактного лица маскируются до отправки в модель.

Сценарий 2 · Компания «Меридиан» Диалог с данными

Разложение маржи по факторам

Не «маржа упала», а почему упала — с раскладкой на факторы, посчитанной по данным компании.

Вопрос в чат

«Почему упала маржа в Q3 к Q2 — разложи по цене, объёму, скидкам, логистике и себестоимости в разрезе регионов и продуктовых групп».

Источники

витрина продаж · себестоимость · логистика · справочник скидок · документ «Политика скидок». Несколько витрин + документ.

Данные заложены точно: маржа Q2 ≈ 20,3% → Q3 ≈ 15,5% при росте объёма. Факторы падения: скидки (акция в Юге), логистика (тарифы Урал/Сибирь), себестоимость (сырьё металлопроката).
Какие функции проверяет
● Диалог с данными (семантический слой) Сборка из нескольких источников Знания / RAG Аудит
Что раскрывает

Голая модель не посчитает по вашим данным, а один дашборд покажет «маржа упала», но не объяснит почему. Версия-ловушка: в корпусе рядом лежит устаревшая политика скидок — ассистент должен сослаться на действующую, а не на первую попавшуюся.

Сценарий 3 · Компания «Полка» (ритейл) Агенты процессов

Голос клиента + цены конкурентов

Внутренние жалобы и возвраты плюс внешние отзывы и цены конкурентов — в одной сводке. Агент безопасно ходит в интернет.

Вопрос в чат

«На что жалуются по бытовой технике за квартал, как наши цены против конкурентов на маркетплейсах, и где мы теряем».

Источники

внутри — обращения, возвраты, продажи; снаружи — отзывы и цены с площадок (агент собирает через AI Guard по белому списку).

Какие функции проверяет
● Агент + безопасный выход в интернет Сборка из нескольких источников Знания / RAG Диалог с данными Аудит
Что раскрывает

Агент дополняет корпоративные данные внешними и сводит в одну картину; можно поставить на расписание (еженедельный дайджест). Выход в сеть — только через AI Guard по белому списку, на чтение; корпоративные данные наружу не уходят, каждый поход в сеть — в аудите.

Сценарий 4 · Компания «Меридиан» Безопасность · доступ

RBAC: один вопрос — разные ответы по ролям

Три роли задают один и тот же вопрос — и каждый получает ровно то, к чему имеет доступ.

Как показывать

  • «Фонд оплаты труда» → HR-директор видит всё, руководитель — только свой отдел, аналитик — отказ
  • «Воронка сделок M&A» → гендиректор видит, остальные — отказ

Источники

HR-оклады · пайплайн сделок с меткой доступа · матрица ролей. Пять готовых демо-пользователей.

Какие функции проверяет
● RBAC (наследование прав) Диалог с данными Аудит
Что раскрывает

Права наследуются из систем-источников, а не прописываются в промпте. ИИ не становится дырой в контуре доступа — прямой ответ на возражение «а не увидит ли сотрудник через ИИ лишнее».

Сценарий 5 · Компания «Меридиан» Безопасность · утечка

ИБ-правило «это наружу не уходит»

ПДн маскируются, коммерческая тайна не покидает периметр — по правилам, которые ИБ настроил заранее (без разработчиков).

Три такта на демо

  • Запрос с ПДн → во внешнюю модель уходит токенами, ответ пользователю — деанонимизирован
  • Запрос про эксклюзивные условия договора → распознаётся как секрет и наружу не выпускается
  • «Суммы незакрытых сделок» → срабатывает правило → запрет

Источники

документы и таблицы с ПДн · база секретов ИБ (на естественном языке) · журнал аудита.

Какие функции проверяет
● Маскирование ПДн ● DLP / коммерческая тайна Знания / RAG Аудит
Что раскрывает

Третий путь между «запретить ИИ» и «слить всё вендору». Секрет распознаётся семантически, а не regex («наш ключевой контрагент» ловится без дословного совпадения). Каждое решение — в аудите.

Сценарий 6 · Компания «Меридиан» Знания / RAG

Юридический ассистент: претензия со ссылками (чат по знаниям)

Ассистент отвечает по внутренним документам со ссылками на конкретные пункты — и честно говорит, когда ответа в корпусе нет.

Вопрос в чат

«Обоснуй отказ в оплате ООО "Альфа" за срыв сроков поставки — подготовь черновик претензии со ссылками на пункты договора и наш регламент».

Источники

договор с «Альфа» (пункты о сроках и приёмке) · регламент оплаты поставщикам · шаблон претензии. Несколько документов, а не один.

Какие функции проверяет
● Знания / RAG (ответ со ссылками на пункты) Сборка из нескольких документов Аудит
Что раскрывает

Ответ строится на ваших документах с цитатами на конкретные пункты, а не «из головы» (механизм RAG). Честность: на вопрос, которого нет в корпусе, ассистент отвечает «не нашёл», а не выдумывает. Версии: цитирует действующую редакцию регламента, а не устаревшую.

03 · Применение

Как подбирать сценарии под встречу

От простого доступного (данные) к сложному активному (агент). Безопасность показывать встроенной по ходу, а не отдельным слайдом.
