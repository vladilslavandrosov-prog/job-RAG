# База знаний по платформе «Синапс.Инсайт»

AI-платформа корпоративных данных. Документация собирается по мере поступления скриншотов интерфейса — каждый раздел меню описан отдельной статьёй.

## Структура платформы (по левому меню)

- **Чат** — [описан](chat.md): история диалогов, выбор модели/агента, экспорт в PDF, переключатель «Рассуждения»
- **Мои шаблоны** — [описан](moi-shablony.md): курируемые образцы ответов, recall на похожий вопрос, строгий vs обычный режим
- **Источники**
  - [Документы](istochniki-dokumenty.md) — реестр загруженных источников, статус индексации, фрагменты, домены/коллекции
- **Задачи** — [описан](zadachi-review-pipeline.md) целиком, как единый конвейер модерации:
  - Предложения, Агенты на утверждении, Статистика, Очередь обработки, Промпты персон
- **Калибровка**
  - [Калибровка детектора](kalibrovka-detektora-i-otladka.md) — пороги детектора таблиц
  - [Политики поиска](kalibrovka-politiki-poiska.md) — ранжирование чанков, планировщик/реплан, роутинг вопросов
  - [Отладка сессий](kalibrovka-detektora-i-otladka.md) — разбор диалогов по инструментам/плану/ответам
- **Управление данными** — [описан](upravlenie-dannymi.md) целиком:
  - Анализ схем, Граф процедур, Граф код→таблица, Граф доступа
- **Каталог** — не описан
- **Агенты** — [описан](agenty.md): конструктор агентов на «канвасе», согласование дата-стюард → ИБ
- **Администрирование** — не описан
- **Мониторинг** — не описан

## Готовые HTML-версии

`docs/platform/html/synaps-insait-baza-znaniy.html` — все статьи склеены в один самодостаточный HTML-файл с общим визуальным стилем и рабочей навигацией между разделами (переключение через JS, без перезагрузки страницы). В шапке сайта — краткое объяснение, что такое RAG-агент, и глоссарий терминов, отдельно от меню платформы. Пункты меню без статьи помечены пунктирным бейджем «ещё не описано».

## Что важно знать о платформе в целом

- Платформа одновременно обслуживает несколько бизнес-доменов в одном инстансе: брокерское/инвестиционное направление, документы по охране труда, кредитный риск и взыскание задолженности.
- Инструмент разбора диалогов («Отладка сессий») в текущем окружении не подключён («Аудит-БД не сконфигурирована»), поэтому детальный разбор конкретных сессий пока приходится делать вручную.
- Селектор модели в чате включает `OpenAI/gpt-5.4` — при использовании с клиентскими данными это стоит сверить с требованием ТЗ о том, что данные не должны покидать периметр компании.
- Граф доступа реализует row-фильтры и маски по персонам и пользователям на уровне `схема.таблица`/`схема.таблица.колонка` — то есть разграничение доступа к данным уже есть как механизм платформы, а не требует проектирования с нуля.
