# Раздел «Администрирование»: пользователи платформы

Точка входа — пункт **«Администрирование»** в левом меню платформы. Он ведёт в отдельный раздел с собственным верхним меню, где нужный экран — **«Рабочее место ИБ» → «Пользователи»** (`/dlp/users/`).

**Важно про порядок действий.** Это не два независимых экрана — учётная запись сначала заводится в **Каталоге** (встроенный OpenMetadata), и только после этого в «Администрировании» появляется/настраивается соответствующая запись (связь — через поле **OM User ID**, которое подтягивается синхронизацией). Идти сразу в «Администрирование», минуя каталог, — неверный порядок.

## Список пользователей

Экран «Пользователи» (`/dlp/users/`) в «Администрировании» — таблица со столбцами: Email, Имя, **OM User ID**, Лимит токенов/день, Моделей, Статус.

## Как создать пользователя с правами администратора

**Этап 1 — создать пользователя в Каталоге (OpenMetadata)**

1. Откройте **«Каталог»** → **«Настройки»** → **«Команды и пользователи»** → **«Админы»**.
2. Нажмите **«Добавить объект „Админ“»**.
3. Заполните поле **«Электронная почта»** (обязательное поле) и, при желании, — **«Отображаемое имя»**.
4. Задайте пароль — автогенерацией или вручную.
5. Включите тумблер **«Админ»**.
6. Нажмите **«Создать»**.

**Этап 2 — настроить права в Администрировании**

1. Откройте **«Администрирование» → «Рабочее место ИБ» → «Пользователи»**.
2. Найдите созданного на этапе 1 пользователя по email — поле **OM User ID** у него должно быть уже заполнено синхронизацией с OpenMetadata.
3. В выпадающем списке **«Роль»** выберите **«Администратор (все провайдеры)»**.
4. При необходимости задайте **«Лимит токенов в день»** (0 — без лимита, применяется суммарно по всем моделям).
5. Сохраните.

Поле **OM User ID** вручную не заполняется — оно приходит из синхронизации с Каталогом (этап 1).

> **Открытый вопрос.** Не проверено на практике, появляется ли пользователь на экране `/dlp/users/` автоматически сразу после создания в Каталоге, или его дополнительно нужно завести там же через «+Добавить» (указав тот же email, чтобы синхронизация связала записи по OM User ID), и с какой задержкой происходит сама синхронизация. Стоит зафиксировать по факту первого реального прогона.

## Полный список ролей

| Роль | Доступные LLM-провайдеры |
|---|---|
| — без роли (все провайдеры разрешены) — | все |
| **Администратор (все провайдеры)** | все |
| Внешние провайдеры разрешены | yandexgpt, gigachat, ollama, anthropic, openai |
| Только внутренние провайдеры | yandexgpt, gigachat, ollama |

> **Открытый вопрос.** Подсказка под полем «Роль» в интерфейсе описывает его как настройку, которая «определяет доступные LLM-провайдеры» — то есть по буквальному описанию UI это в первую очередь тонкая настройка доступа к провайдерам, а не переключатель административных прав над самой платформой (разделами вроде «Администрирование»/«Рабочее место ИБ»). При этом по эффекту на доступные провайдеры роли «Администратор (все провайдеры)» и «— без роли —» совпадают. Не проверено на практике, даёт ли роль «Администратор» что-то сверх этого (например, доступ к разделу «Пользователи» для управления другими учётными записями) — при создании тестового администратора стоит зафиксировать в комментарии, что именно изменилось в правах после назначения этой роли, и при возможности сверить с командой платформы.

## Карточка пользователя (после создания)

Открыв уже созданного пользователя из списка, помимо полей формы создания видно:

- **Пользователь активен** — чекбокс, снятие деактивирует доступ без удаления записи.
- **Права на модели** — точечные разрешения/блокировки по конкретным моделям поверх роли, с отдельным лимитом токенов/день на каждую модель. Если модель не добавлена в список — доступ к ней разрешён по умолчанию (по общему лимиту).
- **Персональные API-ключи** (`/llm/v1`, OpenWebUI) — создание долгоживущих ключей для внешнего LLM-шлюза (Base URL `https://<origin>/llm/v1`, ключ передаётся как API Key). Квота — 5 активных ключей на пользователя, у каждого ключа своё имя и срок жизни в днях (0 — бессрочно).

## Как это связано с каталогом (OpenMetadata)

«Админ» в Каталоге (форма `/create-user` во встроенном OpenMetadata, тумблер **«Админ»**) и «Администратор (все провайдеры)» в «Администрировании» — не одно и то же право, но одно **обязательное условие** для другого: без учётной записи, созданной в Каталоге на этапе 1, соответствующая запись не появится (или не свяжется по email) на экране `/dlp/users/`.

- Каталог/OpenMetadata — доступ к Data Assets, lineage, глоссарию и т.п.
- «Рабочее место ИБ» / «Пользователи» — доступ к самой AI-платформе (чат, выбор LLM-провайдера, лимиты токенов, персональные API-ключи).

Поле **OM User ID** на странице `/dlp/users/` — это и есть связь между двумя записями (идентификатор из OpenMetadata). Но сами права в двух панелях настраиваются раздельно: тумблер «Админ» в Каталоге не выставляет автоматически роль «Администратор» в «Администрировании» — это нужно сделать вручную на этапе 2.
