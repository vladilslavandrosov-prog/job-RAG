# Раздел «Администрирование»: пользователи платформы

Точка входа — пункт **«Администрирование»** в левом меню платформы. Он ведёт в отдельный раздел с собственным верхним меню, где нужный экран — **«Рабочее место ИБ» → «Пользователи»** (`/dlp/users/`).

**Важно про порядок действий.** Учётная запись сначала заводится в **Каталоге** (встроенный OpenMetadata), и только после этого отдельно заводится в «Администрировании». Идти сразу в «Администрирование», минуя каталог, — неверный порядок: без пользователя, заранее созданного в Каталоге, назначать ему полноценные права негде.

**Проверено на практике (12.08.2026).** Создание Admin-пользователя в Каталоге не создаёт запись на `/dlp/users/` автоматически. Пользователь заводится там отдельно, вручную, с тем же email. После этого поле **OM User ID** в карточке пользователя показывает `None`.

## Список пользователей

Экран «Пользователи» (`/dlp/users/`) в «Администрировании» — таблица со столбцами: Email, Имя, **OM User ID**, Лимит токенов/день, Моделей, Статус.

## Как создать пользователя с правами администратора

**Этап 1 — создать пользователя в Каталоге (OpenMetadata)**

1. Откройте **«Каталог»** → **«Настройки»** → **«Команды и пользователи»** → **«Админы»**.
2. Нажмите **«Добавить объект „Админ“»**.
3. Заполните поля **«Электронная почта»** и **«Отображаемое имя»** (оба обязательные).
4. Задайте пароль — автогенерацией или вручную.
5. Включите тумблер **«Админ»**.
6. Нажмите **«Создать»**.

**Этап 2 — создать и настроить права в Администрировании**

Пользователь с этапа 1 **не появляется на экране `/dlp/users/` сам** — его нужно завести здесь отдельно.

1. Откройте **«Администрирование» → «Рабочее место ИБ» → «Пользователи»**.
2. Нажмите **«+Добавить»**.
3. В форме «Новый пользователь» заполните **Email** и **Имя** — те же, что использовались на этапе 1. Поле **OM User ID** оставьте пустым (плейсхолдер «uuid из OpenMetadata»).
4. В выпадающем списке **«Роль»** выберите **«Администратор (все провайдеры)»**.
5. При необходимости задайте **«Лимит токенов в день»** (0 — без лимита, применяется суммарно по всем моделям).
6. Нажмите **«Создать»**.

После сохранения на карточке пользователя (`/dlp/users/<id>`) поле **OM User ID** показывает `None` — см. «Проверено на практике» выше.

## Полный список ролей

| Роль | Доступные LLM-провайдеры |
|---|---|
| — без роли (все провайдеры разрешены) — | все |
| **Администратор (все провайдеры)** | все |
| Внешние провайдеры разрешены | yandexgpt, gigachat, ollama, anthropic, openai |
| Только внутренние провайдеры | yandexgpt, gigachat, ollama |

## Карточка пользователя (после создания)

Открыв уже созданного пользователя из списка, помимо полей формы создания видно:

- **Пользователь активен** — чекбокс, снятие деактивирует доступ без удаления записи.
- **Права на модели** — точечные разрешения/блокировки по конкретным моделям поверх роли, с отдельным лимитом токенов/день на каждую модель. Если модель не добавлена в список — доступ к ней разрешён по умолчанию (по общему лимиту).
- **Персональные API-ключи** (`/llm/v1`, OpenWebUI) — создание долгоживущих ключей для внешнего LLM-шлюза (Base URL `https://<origin>/llm/v1`, ключ передаётся как API Key). Квота — 5 активных ключей на пользователя, у каждого ключа своё имя и срок жизни в днях (0 — бессрочно).

## Как это связано с каталогом (OpenMetadata)

«Админ» в Каталоге (форма `/create-user` во встроенном OpenMetadata, тумблер **«Админ»**) и «Администратор (все провайдеры)» в «Администрировании» — не одно и то же право, и это два **раздельных, независимых** действия, а не одна сквозная синхронизация:

- Каталог/OpenMetadata — доступ к Data Assets, lineage, глоссарию и т.п.
- «Рабочее место ИБ» / «Пользователи» — доступ к самой AI-платформе (чат, выбор LLM-провайдера, лимиты токенов, персональные API-ключи).

Поле **OM User ID** на странице `/dlp/users/` по замыслу должно быть связью между двумя записями (идентификатор из OpenMetadata) — так описано в подсказке интерфейса. На практике при создании пользователя с тем же email в обеих системах это поле осталось `None`: связки по факту не произошло. Тумблер «Админ» в Каталоге не выставляет автоматически роль «Администратор» в «Администрировании» — обе стороны нужно настраивать вручную, этап за этапом.

### Профиль пользователя в Каталоге

Открыв пользователя в OpenMetadata (`/users/<имя>`), видно карточку профиля с вкладками «Активность», «Задачи», «Мои данные», «Подписки», «Разрешения», а также блоки «Персона», «Домены», «Команды» и **«Роли»** (где после создания корректно виден назначенный «Admin», плюс унаследованные роли вроде «Data Consumer»). Через меню «⋮» в углу карточки доступно **«Изменить объект „пароль“»** — смена пароля отдельно от создания. Требования к паролю: 8–56 символов, минимум одна заглавная буква, одна строчная, одна цифра и один спецсимвол (например, `!`, `%`, `@`, `#`).
