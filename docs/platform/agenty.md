# Раздел «Агенты»

Каталог и конструктор агентов платформы. Новый агент собирается на визуальном конструкторе («канвасе»), после чего проходит согласование: сначала у дата-стюарда — проверяются домены данных, узлы и параметры агента (эта стадия обозначена в интерфейсе аббревиатурой «DS»), — затем у информационной безопасности. Только после обеих стадий агент появляется в селекторе чата. Существующего агента можно редактировать на том же канвасе как новую версию.

Экран показывает список активных агентов (агент, тип, наличие canvas-flow) и отдельно — заявки текущего пользователя, ожидающие согласования.

В системе сосуществуют два класса агентов: системные, без визуального flow — вероятно, это как раз то, чем управляют ролевые «Промпты персон» из раздела «Задачи», — и канвасные, с полноценным визуально сконструированным графом обработки, которые и проходят согласование дата-стюард → информационная безопасность.

Среди примеров агентов есть тип «Closed-book RAG» — агент, сознательно отвечающий по собственным знаниям модели, без обращения к поиску. Это не противоречие идее RAG-платформы, а рабочий инструмент: такой агент может служить эталоном для сравнения (что ответила бы модель без доступа к корпоративным данным) или обрабатывать вопросы, для которых поиск не нужен — например, общие вопросы, не связанные с данными компании.
