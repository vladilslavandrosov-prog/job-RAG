# Раздел «Чат»

Главный рабочий экран платформы «Синапс.Инсайт» — интерфейс диалога с RAG-агентом. Экран состоит из двух панелей: слева — список чатов (полнотекстовый поиск по чатам, группировка по дате, история сессий), справа — сама переписка.

## Верхняя панель диалога

- **+ Новый чат** — начать новую сессию.
- **‹ Скрыть историю** — свернуть панель списка чатов.
- **↓ PDF** — экспорт текущего диалога в PDF; активна только когда в чате есть сообщения.
- **Модель** — выбор LLM, обрабатывающей диалог. Среди опций — `OpenAI/gpt-5.4 · veai`.
- **Агент** — выбор роли/персоны для чата (например, «Синапс.Инсайт — Аналитик»).
- **Рассуждения** — переключатель, показывающий ход рассуждений модели прямо в интерфейсе чата.
- Переключатель светлой/тёмной темы.

Роль (персона) задаёт стиль и фокус ответов агента в системном чате. На «канвасных» (governed) агентов персоны не влияют — это настраивается отдельно, через раздел «Агенты», где такие агенты собираются на визуальном конструкторе и проходят согласование перед публикацией.

## Модель и периметр данных

Наличие `OpenAI/gpt-5.4` в селекторе моделей стоит сверить с требованием ТЗ о том, что данные не должны покидать периметр компании (раздел 3.2, критерий приёмки №8): если это вызов облачного API, а не внутренний прокси со схожим названием, это прямое несоответствие критическому требованию.

Внутренний методический материал по продажам платформы (`docs/sales-enablement/`) даёт косвенную подсказку про суффикс «veai»: партнёр «Veai» там описан как биллинговый шлюз для оплаты иностранных LLM-провайдеров в рублях и одновременно как соисполнитель нескольких клиентских пилотов — то есть суффикс, вероятнее всего, обозначает именно этот шлюз/биллинговый прокси, через который проходит вызов модели. Тот же материал описывает компонент «AI Gateway», через который идут все ИИ-запросы компании, с фильтром, вырезающим чувствительные данные из текста непосредственно **перед** отправкой в облачную модель. Это подтверждает, что вызов внешнего облака действительно происходит — маскирование чувствительных полей не то же самое, что нераскрытие периметра целиком, — поэтому соответствие критерию №8 стоит сверять по точной формулировке требования, а не считать вопрос закрытым.
