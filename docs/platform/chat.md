# Раздел «Чат»

> Скриншот: главный экран `Разделы → Чат` (`https://sinapse.itq-group.com:12452/shell/chat`).

## Назначение экрана

Основной рабочий экран платформы — интерфейс диалога с RAG-агентом, аналогичный тому, что видно в логе диалога D8-014 (`docs/analysis/case-01-d8-014-brief.md`). Состоит из двух панелей: список чатов слева и сама переписка справа.

## Элементы экрана

### Панель истории чатов (слева от диалога)

| Элемент | Назначение |
|---|---|
| Поиск по чатам | Полнотекстовый поиск среди сохранённых диалогов |
| Группировка по дате («Сегодня») | Чаты сгруппированы по дням |
| Список чатов | Каждый чат — отдельная сессия с сохранённой историей (на скриншоте: один чат «какие документы есть...») |

### Верхняя панель диалога

| Элемент | Назначение |
|---|---|
| **+ Новый чат** | Начать новую сессию диалога |
| **‹ Скрыть историю** | Свернуть панель списка чатов, освободив место под диалог |
| **↓ PDF** | Экспорт текущего диалога в PDF (неактивна, пока в чате нет сообщений) — именно так выглядят присланные ранее логи (`docs/sources/d8-014-chat-transcript.pdf`) |
| **Модель** — `OpenAI/gpt-5.4 · veai` | Выбор LLM, обрабатывающей диалог |
| **Агент** — `★ Синапс.Инсайт — Аналитик (пла...)` | Выбор агента/роли-персоны для чата — связано с разделом «Задачи → Промпты персон» (см. `docs/platform/README.md`, ещё не описан отдельно) |
| ☆ (чекбокс со звездой) | Судя по всему — добавить чат/агента в избранное |
| **🔴 Рассуждения** | Переключатель показа «рассуждений» модели (chain-of-thought / промежуточные шаги) прямо в интерфейсе |
| **?** | Справка |
| 🌙 (луна) | Переключатель тёмной/светлой темы интерфейса |

## Наблюдения и связь с проектом

### ⚠️ Модель `OpenAI/gpt-5.4` — потенциальное противоречие с ТЗ по безопасности

Селектор модели показывает вариант **`OpenAI/gpt-5.4 · veai`**. Это существенно, потому что ТЗ (`docs/sources/tz-rag-investment.pdf`, раздел 3.2 «Безопасность») требует:

> «Все данные хранятся исключительно на сервере компании — никакие данные не передаются в облако или третьим лицам»
> «Доступ к компонентам системы (Qdrant, Ollama) ограничен файрволом — только localhost»

и критерий приёмки №8 (раздел 4.1): «Данные не покидают периметр компании», порог **100%**, критичность **Критический**.

Явное упоминание Ollama в ТЗ подразумевает локальные модели без внешних вызовов. Если `OpenAI/gpt-5.4` в этом селекторе — это буквально облачный API OpenAI (а не внутренний прокси/деплой с похожим именем), то выбор такой модели для чата с клиентскими данными **нарушает критический критерий приёмки №8** — часть текста диалога (в т.ч. потенциально персональные данные клиентов) уходила бы за периметр компании.

**Не факт, что это нарушение** — суффикс `veai` может быть названием внутреннего прокси/деплоя (например, собственный inference-шлюз, стилизованный под OpenAI-совместимый API, крутящийся на своём сервере). Это стоит уточнить отдельно, прежде чем делать вывод — но сам факт, что в UI **вообще есть** опция с названием `OpenAI`, при заявленном требовании «данные не покидают периметр», — уже повод для отдельной проверки на комплаенс-уровне, независимо от итогового ответа.

Это прямо связано с находкой 2.3 в `docs/analysis/case-02-tz-deep-analysis-and-proposals.md` (права доступа не Must Have) и стоит добавить туда же отдельным пунктом после уточнения.

### Переключатель «Рассуждения» — частичное перекрытие рекомендации 4.6 из `case-02`

В `case-02-tz-deep-analysis-and-proposals.md` (раздел 4.6) была рекомендация завести отдельный «технический reasoning log» — лог промежуточных шагов (SQL, извлечённые чанки), недоступный обычному аудиту, но нужный для разбора инцидентов вроде Кейса 01. Переключатель «Рассуждения» на этом экране, похоже, выводит что-то из этого прямо в интерфейс чата (chain-of-thought), а не только в служебный лог. Стоит на будущих скриншотах проверить: что именно показывает «Рассуждения» — реальные шаги (сгенерированный SQL, найденные чанки), или только текстовое рассуждение модели без привязки к конкретным вызовам инструментов.

### Выбор агента/персоны

Дропдаун «Агент» с опцией «Синапс.Инсайт — Аналитик» подтверждает, что в системе есть заранее сконфигурированные роли/персоны (см. пункт левого меню «Задачи → Промпты персон», ранее отмеченный как неописанный) — то есть один и тот же RAG-движок обслуживает разных пользователей через разные преднастроенные системные промпты в зависимости от роли (аналитик, менеджер фронт-офиса и т.д. — ср. роли пользователей из ТЗ, раздел 1.3).
