# Раздел «Управление данными»: схемы, lineage, код и доступ

## Анализ схемы таблицы

Инструмент, которым система анализирует структуру конкретной таблицы БД по её полному имени (FQN, `схема.таблица`) — колонки, типы, вероятно, генерирует описания полей для использования в тексте-в-SQL пайплайне: прежде чем агент сможет надёжно писать SQL-запросы к таблице, платформе нужно знать её схему.

## Граф процедур (lineage)

Инструмент отслеживания происхождения и связей хранимых процедур — какая процедура что вызывает, от каких таблиц зависит. Пересчёт графа можно ограничить только устаревшими или новыми элементами — инкрементально, по хэшу, без изменений это no-op, — тот же принцип, что применяется и к синхронизации документов.

## Граф код→таблица

Экран из трёх связанных блоков. Первый — извлечение из код-коллекции: коллекция типа «Кодовая база» привязывается к целевому сервису или базе данных из реестра сервисов платформы («ОМ») и подключается к репозиторию. Второй — пересборка lineage-связей документов с таблицами и процедурами прямо из уже проиндексированных чанков, без повторного эмбеддинга: когда каталог таблиц и процедур растёт, система может задним числом найти в уже загруженных документах упоминания вновь распознанных сущностей. Третий блок — синхронизация с GitLab, с тремя режимами: инкремент (только новые коммиты), сверка (reconcile по дереву репозитория, самостоятельно устраняющая расхождения) и полный пере-синк.

## Граф доступа

Row-фильтры и маски для персон и пользователей, с ключами на уровне `схема.таблица` и `схема.таблица.колонка`. Экран разделён на вкладки «Политики доступа» (настройка фильтров и масок по конкретной персоне) и «Карта покрытия» (какие таблицы и колонки уже защищены политиками, а какие — нет).

Это фактическая реализация разграничения доступа на уровне данных: row-политики решают, какие строки видны конкретной персоне, маски — какие колонки скрыты или заменены. Такой механизм способен одновременно решить две задачи, которые иначе требовали бы отдельного проектирования: ограничить менеджера фронт-офиса кругом его собственных клиентов и замаскировать колонки с персональными данными для тех ролей, кому не положено видеть их в открытом виде, оставив точный поиск по ФИО и ИНН доступным только тем, кому это разрешено по должности.
