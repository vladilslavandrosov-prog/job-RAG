## Введение и область применения

Настоящий документ описывает процедуры установки, настройки и эксплуатации платформы Синапс.Инсайт для персонала ИТ-эксплуатации (DevOps/SRE) и администраторов баз данных.

Документ охватывает:

-   Подготовку инфраструктуры для двух вариантов развёртывания --- Docker Compose и Kubernetes

-   Пошаговую установку и первоначальную инициализацию платформы

-   Управление пользователями, ролями и коллекциями данных

-   Подключение источников данных и управление эмбеддерами

-   Резервное копирование, обновление и мониторинг

  ---------------------------------------------------------------------------------------------------------------------------------------------------
  *Документ не охватывает сборку образов из исходного кода. Предполагается использование готовых образов из реестра, предоставленного поставщиком.*

  ---------------------------------------------------------------------------------------------------------------------------------------------------

## Предварительные требования

### 2.1 Docker Compose --- подготовка хоста

Требования к хосту:

-   ОС: Rocky Linux 8/9, RHEL 8/9, AltLinux P10/P11, Ubuntu 22.04 LTS

-   Docker Engine 24.0+ и Docker Compose v2.20+

-   Минимум 32 ГБ RAM, 16 vCPU, 500 ГБ свободного места на диске данных

-   Открытый входящий порт 443 (HTTPS)

Проверка версий Docker:

+-----------------------------------------------------------------------+
| docker \--version                                                     |
|                                                                       |
| \# Docker version 24.0.x или выше                                     |
|                                                                       |
| docker compose version                                                |
|                                                                       |
| \# Docker Compose version v2.20.x или выше                            |
+-----------------------------------------------------------------------+

Настройка системных лимитов (требуется для Qdrant):

+-----------------------------------------------------------------------------------+
| \# /etc/security/limits.conf или /etc/systemd/system/docker.service.d/limits.conf |
|                                                                                   |
| \* soft nofile 65536                                                              |
|                                                                                   |
| \* hard nofile 65536                                                              |
+-----------------------------------------------------------------------------------+

  ----------------------------------------------------------------------------------------------------------------------------------------------
  **⚠ Внимание:** Qdrant требует ulimits nofile ≥ 65536. Без этой настройки Qdrant не запустится или будет нестабильно работать под нагрузкой.

  ----------------------------------------------------------------------------------------------------------------------------------------------

### 2.2 Kubernetes --- подготовка кластера

Требования к кластеру:

-   Kubernetes 1.26+ (поддерживаются Deckhouse, Vanilla K8s, OpenShift 4.12+)

-   Helm 3.12+

-   Наличие StorageClass с поддержкой ReadWriteOnce (Ceph RBD, local-path, NFS)

-   Минимальные ресурсы кластера: 32 vCPU, 64 ГБ RAM, 1 ТБ хранилище

-   Доступ к реестру образов поставщика (или локальный реестр с загруженными образами)

Проверка готовности кластера:

+-----------------------------------------------------------------------+
| kubectl version \--short                                              |
|                                                                       |
| helm version \--short                                                 |
|                                                                       |
| kubectl get nodes                                                     |
|                                                                       |
| kubectl get storageclass                                              |
+-----------------------------------------------------------------------+

## Установка и первоначальная настройка

### 3.1 Docker Compose: развёртывание

Архитектура compose-развёртывания разделена на два стека: data-стек (PostgreSQL, Qdrant, MinIO) и app-стек (все прикладные сервисы). Оба стека работают в одной внешней сети synapse.

**Шаг 1. Создание директорий**

+-----------------------------------------------------------------------+
| mkdir -p /opt/synapse/{data,app,front,monitoring}                     |
|                                                                       |
| mkdir -p /opt/synapse/front/{ssl,dist}                                |
+-----------------------------------------------------------------------+

**Шаг 2. Создание внешней Docker-сети**

  -----------------------------------------------------------------------
  docker network create synapse

  -----------------------------------------------------------------------

**Шаг 3. TLS-сертификат**

Поместите SSL-сертификат и ключ в /opt/synapse/front/ssl/:

+------------------------------------------------------------------------------------+
| \# Самоподписанный сертификат (для пилота/PoC):                                    |
|                                                                                    |
| openssl req -x509 -nodes -days 365 -newkey rsa:2048 \\                             |
|                                                                                    |
| -keyout /opt/synapse/front/ssl/tls.key \\                                          |
|                                                                                    |
| -out /opt/synapse/front/ssl/tls.crt \\                                             |
|                                                                                    |
| -subj \'/CN=app.example.local\' \\                                                 |
|                                                                                    |
| -addext \'subjectAltName=DNS:app.example.local,DNS:om.example.local,IP:SERVER_IP\' |
|                                                                                    |
| \# Для production --- используйте сертификат от корпоративного УЦ.                 |
+------------------------------------------------------------------------------------+

  -----------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  *При использовании самоподписанного сертификата его необходимо добавить в доверенные хранилища всех клиентских машин. Без этого SSO модуля OpenMetadata не будет работать.*

  -----------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**Шаг 4. Развёртывание data-стека**

Разместите /opt/synapse/data/docker-compose.yml с содержимым из дистрибутива поставщика. Ключевые параметры:

+-----------------------------------------------------------------------+
| \# /opt/synapse/data/docker-compose.yml (фрагмент)                    |
|                                                                       |
| services:                                                             |
|                                                                       |
| postgres:                                                             |
|                                                                       |
| image: postgres:16                                                    |
|                                                                       |
| volumes:                                                              |
|                                                                       |
| \- pg-data:/var/lib/postgresql/data                                   |
|                                                                       |
| env_file: .env                                                        |
|                                                                       |
| networks: \[synapse\]                                                 |
|                                                                       |
| qdrant:                                                               |
|                                                                       |
| image: qdrant/qdrant:v1.13.6                                          |
|                                                                       |
| volumes:                                                              |
|                                                                       |
| \- qdrant-data:/qdrant/storage                                        |
|                                                                       |
| ulimits:                                                              |
|                                                                       |
| nofile: { soft: 65536, hard: 65536 }                                  |
|                                                                       |
| networks: \[synapse\]                                                 |
|                                                                       |
| minio:                                                                |
|                                                                       |
| image: minio/minio                                                    |
|                                                                       |
| command: server /data \--console-address \':9001\'                    |
|                                                                       |
| env_file: .env                                                        |
|                                                                       |
| networks: \[synapse\]                                                 |
|                                                                       |
| networks:                                                             |
|                                                                       |
| synapse:                                                              |
|                                                                       |
| external: true                                                        |
+-----------------------------------------------------------------------+

**Шаг 5. Инициализация баз данных**

После запуска data-стека создайте роли и базы данных:

+----------------------------------------------------------------------------+
| docker compose -f /opt/synapse/data/docker-compose.yml up -d               |
|                                                                            |
| \# Подождать готовности PostgreSQL                                         |
|                                                                            |
| docker compose -f /opt/synapse/data/docker-compose.yml exec postgres \\    |
|                                                                            |
| pg_isready -U postgres                                                     |
|                                                                            |
| \# Применить SQL-скрипт инициализации из дистрибутива                      |
|                                                                            |
| docker compose -f /opt/synapse/data/docker-compose.yml exec -T postgres \\ |
|                                                                            |
| psql -U postgres -f /docker-entrypoint-initdb.d/init.sql                   |
|                                                                            |
| \# Создать бакет MinIO                                                     |
|                                                                            |
| docker compose -f /opt/synapse/data/docker-compose.yml exec minio \\       |
|                                                                            |
| mc mb /data/doc-uploads                                                    |
+----------------------------------------------------------------------------+

**Шаг 6. Настройка переменных окружения**

Скопируйте шаблоны env-файлов из дистрибутива и заполните значения:

+-----------------------------------------------------------------------+
| cp /opt/synapse/app/envs/\*.env.template /opt/synapse/app/envs/       |
|                                                                       |
| \# Отредактируйте каждый \*.env файл:                                 |
|                                                                       |
| \# app.env, agent-runtime.env, orchestrator.env,                      |
|                                                                       |
| \# pii-shield.env, dlp.env, om.env                                    |
+-----------------------------------------------------------------------+

Обязательные переменные для каждого окружения:

  -------------------------- ---------------------------------------------------- -----------------------------
  **Переменная**             **Назначение**                                       **Где используется**

  PUBLIC_ORIGIN              Публичный URL платформы (https://app.example.com)    agent-runtime, orchestrator

  PG_HOST                    Хост PostgreSQL (имя сервиса или IP)                 все сервисы

  QDRANT_HOST                Хост Qdrant                                          agent-runtime, orchestrator

  MINIO_ENDPOINT             Хост MinIO                                           agent-runtime, dwh

  OPENMETADATA_TOKEN         JWT-токен ingestion-bot (см. раздел 3.3)             pii-shield, orchestrator

  PII_TRUSTED_EGRESS_TOKEN   Общий токен pii-shield ↔ agent-runtime (mask-late)   pii-shield, agent-runtime

  LLM_API_KEY                Ключ доступа к LLM-провайдеру                        agent-runtime, orchestrator
  -------------------------- ---------------------------------------------------- -----------------------------

**Шаг 7. Запуск app-стека**

+-----------------------------------------------------------------------+
| cd /opt/synapse/app                                                   |
|                                                                       |
| docker compose up -d                                                  |
|                                                                       |
| \# Проверить статус                                                   |
|                                                                       |
| docker compose ps                                                     |
+-----------------------------------------------------------------------+

### 3.2 Kubernetes: установка через Helm

Дистрибутив поставляется в виде Helm-чарта. Минимальная установка:

+-----------------------------------------------------------------------+
| \# Добавить репозиторий (или использовать локальный архив)            |
|                                                                       |
| helm repo add synapse https://charts.example.com/synapse              |
|                                                                       |
| helm repo update                                                      |
|                                                                       |
| \# Создать namespace                                                  |
|                                                                       |
| kubectl create namespace synapse                                      |
|                                                                       |
| \# Установить с переопределением значений                             |
|                                                                       |
| helm install synapse-insight synapse/synapse-insight \\               |
|                                                                       |
| \--namespace synapse \\                                               |
|                                                                       |
| \--values /path/to/values.yaml \\                                     |
|                                                                       |
| \--wait \--timeout 10m                                                |
+-----------------------------------------------------------------------+

  ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  *Минимальный values.yaml с обязательными параметрами поставляется в составе дистрибутива. Ключевые параметры: image.registry, postgresql.host, ingress.host, llm.apiKey.*

  ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------

### 3.3 Первый запуск: инициализация OpenMetadata

  ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **⚠ Внимание:** На свежей базе данных токен ingestion-bot НЕВАЛИДЕН, даже если GET /api/v1/system/version возвращает 200 --- этот эндпоинт не требует аутентификации. Необходимо выпустить PAT вручную.

  ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Порядок получения валидного токена ingestion-bot:

**Шаг 1. Дождаться полного запуска OpenMetadata**

+-----------------------------------------------------------------------+
| \# Docker Compose:                                                    |
|                                                                       |
| docker compose logs -f openmetadata-server \| grep -i \'started\'      |
|                                                                       |
| \# Kubernetes:                                                        |
|                                                                       |
| kubectl rollout status deployment/openmetadata -n synapse             |
+-----------------------------------------------------------------------+

**Шаг 2. Извлечь и расшифровать JWT**

+-----------------------------------------------------------------------------------+
| \# Получить зашифрованный токен из БД                                             |
|                                                                                   |
| docker compose exec postgres psql -U openmetadata_user -d openmetadata_db -tAc \\ |
|                                                                                   |
| \"SELECT json-\>\'authenticationMechanism\'-\>\'config\'-\>\>\'JWTToken\'         |
|                                                                                   |
| FROM user_entity WHERE name=\'ingestion-bot\'\"                                   |
|                                                                                   |
| \# Расшифровать через сервисный скрипт (в образе pii-shield):                     |
|                                                                                   |
| bash /opt/synapse/om-bootstrap/issue-pat.sh                                       |
|                                                                                   |
| \# Скрипт выводит валидный JWT (\~760 символов)                                   |
+-----------------------------------------------------------------------------------+

**Шаг 3. Обновить токен в env-файлах**

+------------------------------------------------------------------------------+
| \# В om.env, pii-shield.env, orchestrator.env, agent-runtime.env:            |
|                                                                              |
| OPENMETADATA_TOKEN=\<полученный JWT\>                                        |
|                                                                              |
| PII_MCP_DEFAULT_TOKEN=\<тот же JWT\>                                         |
|                                                                              |
| \# Перезапустить затронутые сервисы                                          |
|                                                                              |
| docker compose up -d \--force-recreate pii-shield orchestrator agent-runtime |
+------------------------------------------------------------------------------+

**Шаг 4. Проверить аутентификацию OM**

+-----------------------------------------------------------------------+
| \# Этот эндпоинт требует аутентификации --- должен вернуть 200        |
|                                                                       |
| curl -s -o /dev/null -w \'%{http_code}\' \\                           |
|                                                                       |
| -H \'Authorization: Bearer \${OPENMETADATA_TOKEN}\' \\                |
|                                                                       |
| http://openmetadata-server:8585/api/v1/metadata/types/name/aiApplication      |
|                                                                       |
| \# Ожидается: 200                                                     |
+-----------------------------------------------------------------------+

### 3.4 Миграции баз данных

Порядок применения миграций при первом запуске:

  ---------------- ----------------------------- ---------------------------------------------------------------------------
  **Сервис**       **Механизм**                  **Команда**

  dlp-secret       Alembic (авто в entrypoint)   Автоматически при старте контейнера

  audit-service    init_db (авто при старте)     Автоматически при старте контейнера

  dwh              Alembic (вручную)             docker compose exec dwh-backend sh -c \'cd /app && alembic upgrade head\'

  ---------------- ----------------------------- ---------------------------------------------------------------------------

  -----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

  -----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

## Управление пользователями и ролями

### 4.1 Создание пользователей

Идентичности пользователей управляются в Синапс.Каталоге (OpenMetadata) --- разделы Users / Teams / Roles / Personas. Доступ к данным и политика модели для конкретного пользователя настраиваются в админ-интерфейсе ИБ (ib_ui): раздел **«Пользователи и доступ»**.

### 4.2 Предопределённые роли

  ------------- --------------------------------------------------------------------- -------------------------------------------------------
  **Роль**      **Возможности**                                                       **Ограничения**

  admin         Полный доступ, управление пользователями и конфигурацией              ---

  Data Steward  Глоссарий, метаданные, предложения (proposals), связи термин→данные   Без доступа к настройкам ИБ

  ИБ-админ      Политики маскировки ПДн, аудит, типы ПДн, провайдеры моделей           ---

  аналитик      Доступ к данным по назначенным доменам/коллекциям, аналитика, экспорт  Без доступа к системным настройкам
  ------------- --------------------------------------------------------------------- -------------------------------------------------------

### 4.3 Назначение коллекций пользователю

Доступ к данным предоставляется через назначение коллекций. Коллекция = источник данных + контроль доступа (подробнее о коллекциях --- раздел 6).

Назначение выполняется через бизнес-домены OpenMetadata (роль/персона пользователя → доступные домены) и коллекции ИБ-интерфейса (ib_ui → «Пользователи и доступ»).

  --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  *Пользователь получает доступ к коллекции целиком. Детальное ограничение внутри коллекции по строкам или столбцам --- через политики OPA (конфигурируется поставщиком под конкретный сценарий).*

  --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

## Подключение источников данных

### 5.1 Регистрация коннектора Trino/CedrusData

Каждый источник данных регистрируется как отдельный каталог в конфигурации Trino/CedrusData. Конфигурационный файл размещается в /etc/trino/catalog/ (или смонтированном томе).

Пример конфигурации коннектора PostgreSQL:

+-----------------------------------------------------------------------+
| \# /etc/trino/catalog/source_crm.properties                           |
|                                                                       |
| connector.name=postgresql                                             |
|                                                                       |
| connection-url=jdbc:postgresql://crm-db.example.com:5432/crm          |
|                                                                       |
| connection-user=synapse_readonly                                      |
|                                                                       |
| connection-password=\${ENV:CRM_DB_PASSWORD}                           |
+-----------------------------------------------------------------------+

  ------------------------------------------------------------------------------------------------------------------------------------------------------------
  **⚠ Внимание:** Сервисная учётная запись для подключения к источнику должна иметь права ТОЛЬКО на чтение (SELECT). Права на запись предоставлять не нужно.

  ------------------------------------------------------------------------------------------------------------------------------------------------------------

После добавления конфигурации перезапустить Trino и проверить доступность каталога:

+-----------------------------------------------------------------------+
| docker compose restart trino                                          |
|                                                                       |
| \# Проверить список каталогов                                         |
|                                                                       |
| docker compose exec trino trino \--execute \'SHOW CATALOGS\'          |
|                                                                       |
| \# source_crm должен присутствовать в списке                          |
+-----------------------------------------------------------------------+

### 5.2 Индексирование источника (RAG)

После регистрации коннектора источник необходимо проиндексировать для включения семантического поиска. Коллекция создаётся и индексируется через админ-интерфейс ИБ (ib_ui):

-   Раздел «Коллекции» → Создать / открыть карточку коллекции

-   Загрузка и переиндексация документов --- раздел «Реестр документов»

Платформа автоматически выберет эмбеддинговую модель по типу контента: code-индекс для SQL/DDL, text-индекс для документов и описаний.

  -------------------------------------------------------------------------------------------------------------------------------------------------------
  *Первоначальное индексирование большого источника может занять значительное время. Прогресс загрузки и индексации документов отображается в разделе «Реестр документов».*

  -------------------------------------------------------------------------------------------------------------------------------------------------------

### 5.3 Управление эмбеддерами

Эмбеддеры --- сервисы векторизации текста (Text Embeddings Inference, TEI). Регистрируются в админ-интерфейсе ИБ (ib_ui): раздел **«Провайдеры»** (единый реестр TEI-эмбеддеров и LLM-провайдеров).

  ------------------ ------------------------------ ----------------- ---------------------------
  **Модель**         **Назначение**                 **Размерность**   **Порт TEI по умолчанию**

  bge-m3             Текстовый контент, документы   1024              8099

  jina-code          SQL, программный код           768               8100
  ------------------ ------------------------------ ----------------- ---------------------------

После регистрации провайдеров выполнить синхронизацию моделей: «Провайдеры» → \[провайдер\] → Синхронизировать модели. Затем назначить модель коллекциям (раздел «Коллекции»).

## Управление коллекциями

Коллекция --- основная единица организации данных в платформе. Коллекция соответствует одному логическому источнику данных (схема БД, набор документов, таблица) и одновременно является границей контроля доступа.

### 6.1 Создание коллекции

Админ-интерфейс ИБ (ib_ui) → **«Коллекции»** → Создать. Обязательные поля:

  ---------------- ------------------------------------ -----------------------
  **Поле**         **Описание**                         **Пример**

  Название         Уникальное имя коллекции             sales_crm

  Тип              Тип источника (SQL / Document)       SQL

  Источник         Зарегистрированный коннектор Trino   source_crm.public

  Эмбеддер         Модель для индексирования            bge-m3
  ---------------- ------------------------------------ -----------------------

### 6.2 Переиндексация и очистка

Переиндексация требуется при значительном изменении схемы или содержимого источника. Выполняется через админ-интерфейс ИБ (ib_ui):

-   «Коллекции» → карточка коллекции --- пересоздание либо деактивация коллекции

-   «Реестр документов» --- переиндексация загруженных документов

## Резервное копирование и восстановление

  --------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  *Рекомендуемая частота резервного копирования: PostgreSQL --- ежедневно, Qdrant --- еженедельно (или после крупных переиндексаций), MinIO --- ежедневно инкрементально.*

  --------------------------------------------------------------------------------------------------------------------------------------------------------------------------

### 7.1 PostgreSQL

Резервное копирование:

+-----------------------------------------------------------------------+
| \# Создать дамп всех баз данных                                       |
|                                                                       |
| docker compose exec postgres pg_dumpall -U postgres \\                |
|                                                                       |
| \> /backup/pg_backup\_\$(date +%Y%m%d).sql                            |
|                                                                       |
| \# Или дамп конкретной БД                                             |
|                                                                       |
| docker compose exec postgres pg_dump -U postgres dlp \\               |
|                                                                       |
| \> /backup/dlp\_\$(date +%Y%m%d).sql                                  |
+-----------------------------------------------------------------------+

Восстановление:

+-----------------------------------------------------------------------+
| \# Восстановить из дампа                                              |
|                                                                       |
| docker compose exec -T postgres psql -U postgres \\                   |
|                                                                       |
| \< /backup/pg_backup_20260101.sql                                     |
+-----------------------------------------------------------------------+

### 7.2 Qdrant

Qdrant хранит данные в Docker volume qdrant-data. Резервное копирование:

+-----------------------------------------------------------------------+
| \# Остановить Qdrant перед копированием (для консистентности)         |
|                                                                       |
| docker compose stop qdrant                                            |
|                                                                       |
| \# Скопировать volume                                                 |
|                                                                       |
| docker run \--rm -v synapse_qdrant-data:/data -v /backup:/backup \\   |
|                                                                       |
| alpine tar czf /backup/qdrant\_\$(date +%Y%m%d).tar.gz -C /data .     |
|                                                                       |
| docker compose start qdrant                                           |
+-----------------------------------------------------------------------+

  ------------------------------------------------------------------------------------------------------------------------------------
  *Альтернатива --- использовать Qdrant Snapshot API: POST /collections/{name}/snapshots. Снапшоты создаются без остановки сервиса.*

  ------------------------------------------------------------------------------------------------------------------------------------

### 7.3 MinIO

+-----------------------------------------------------------------------+
| \# Зеркалирование бакета на локальную директорию                      |
|                                                                       |
| docker compose exec minio mc mirror \\                                |
|                                                                       |
| /data/doc-uploads /backup/minio/doc-uploads                           |
|                                                                       |
| \# Или на внешний S3-совместимый таргет:                              |
|                                                                       |
| mc mirror minio/doc-uploads s3target/backup-doc-uploads               |
+-----------------------------------------------------------------------+

## Обновление платформы

  -----------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **⚠ Внимание:** Перед обновлением обязательно выполните резервное копирование PostgreSQL и Qdrant (разделы 7.1, 7.2). Обновление без резервной копии --- на ваш риск.

  -----------------------------------------------------------------------------------------------------------------------------------------------------------------------

### 8.1 Docker Compose

Процедура обновления:

**Шаг 1. Пометить текущие образы как :prev**

+-----------------------------------------------------------------------+
| for svc in pii-shield dlp-secret agent-runtime orchestrator; do       |
|                                                                       |
| docker tag \${svc}:latest \${svc}:prev                                |
|                                                                       |
| done                                                                  |
+-----------------------------------------------------------------------+

**Шаг 2. Загрузить новые образы из реестра поставщика**

+-----------------------------------------------------------------------+
| docker compose pull                                                   |
|                                                                       |
| \# или загрузить из tar-архива:                                       |
|                                                                       |
| docker load -i /path/to/synapse-images-v1.1.tar.gz                    |
+-----------------------------------------------------------------------+

**Шаг 3. Применить обновление**

+---------------------------------------------------------------------------+
| docker compose up -d \--force-recreate                                    |
|                                                                           |
| \# Применить миграции (если есть в release notes)                         |
|                                                                           |
| docker compose exec dwh-backend sh -c \'cd /app && alembic upgrade head\' |
+---------------------------------------------------------------------------+

**Шаг 4. Откат при необходимости**

+-----------------------------------------------------------------------+
| \# Откатиться на предыдущую версию                                    |
|                                                                       |
| for svc in pii-shield dlp-secret agent-runtime orchestrator; do       |
|                                                                       |
| docker tag \${svc}:prev \${svc}:latest                                |
|                                                                       |
| done                                                                  |
|                                                                       |
| docker compose up -d \--force-recreate                                |
+-----------------------------------------------------------------------+

### 9.2 Prometheus и Grafana

Стек мониторинга (Prometheus + Grafana) поставляется в составе дистрибутива в директории /opt/synapse/monitoring/.

  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **⚠ Внимание:** Prometheus занимает порт 9090. Если на хосте работает Cockpit или другой сервис на этом порту --- использовать порт 9091 (host-port mapping в docker-compose.yml мониторинга).

  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Таргеты Prometheus и ожидаемые метрики:

  ---------------- ---------------------------- ------------------------------------
  **Job**          **Эндпоинт**                 **Ключевые метрики**

  pii-shield       pii-shield:8093/metrics      Запросы, задержки, активные сессии

  dlp-secret       dlp-secret:8089/metrics      Операции маскирования, ошибки

  agent-runtime    agent-runtime:8000/metrics   Запросы агентов, время ответа

  orchestrator     orchestrator:8000/metrics    Задачи, очередь, ошибки

  qdrant           qdrant:6333/metrics          Векторные операции, память

  tei-bge-m3       tei-host:8099/metrics        Запросы эмбеддинга, задержка
  ---------------- ---------------------------- ------------------------------------

Grafana доступна на порту 3000. Преднастроенные дашборды поставляются из директории pii-shield/docker/grafana/provisioning/. Доступ в production --- через SSH-туннель:

+---------------------------------------------------------------------------+
| ssh -L 3000:monitoring-host:3000 -L 9091:monitoring-host:9091 user@server |
|                                                                           |
| \# Затем открыть http://localhost:3000 в браузере                         |
+---------------------------------------------------------------------------+
